# HumanProof 3分デモ動画 台本

想定尺: 2分50秒〜3分  
画面: 提出サイトを実際に操作  
原則: 画面にある文字を全部読み上げない

## 0:00–0:18 課題

**画面**  
トップからNIGHT SCREENの登録画面へ。

**ナレーション**  
「18歳以上か確認したいだけなのに、サービスへ氏名、生年月日、住所、顔写真、身分証画像まで渡す。いまの本人確認は、必要な事実と、集める本人情報が釣り合わないことがあります。」

## 0:18–0:35 入口

**画面**  
従来の確認とHumanProofの2択を見せる。

**ナレーション**  
「HumanProofは本人確認AIではありません。サービスの本人情報要求を、その場に必要な証明へ変えるTrust Layerです。ここでは18歳以上向けの動画サービスに登録します。」

**操作**  
`HumanProofを使う` を押す。

## 0:35–1:02 共有確認と同意

**画面**  
共有する2証明、渡さない5項目を映す。

**ナレーション**  
「NIGHT SCREENへ共有するのは、『18歳以上』『実在する人』という2つの事実だけです。氏名、正確な生年月日、住所、顔写真、身分証画像は、このサービスへ渡しません。」

「このPoCのIssuerは模擬です。本番eKYCには接続していません。また、証明自体は個人に関する属性で、匿名化ではありません。」

**操作**  
`この2つだけ共有する` を押す。

## 1:02–1:24 発行と検証

**画面**  
Live Transactionの4行が進む。

**ナレーション**  
「同意後、Demo Issuerが期限付きの署名証明を発行します。NIGHT SCREENは署名、宛先、期限、失効状態を検証します。」

## 1:24–1:48 サービス上の成果

**画面**  
NIGHT SCREENの登録完了、2 / 0 / 5を見せる。

**ナレーション**  
「HumanProof内でVALIDと出て終わりではありません。動画サービスへ戻り、登録が完了します。共有した証明は2つ。AIへ送った利用者の本人情報値は0。サービスへ渡していない項目は5つです。」

「ここで0なのはAIへ送った本人情報値です。個人情報全体が0という意味ではありません。」

## 1:48–2:13 AIとOrcaRouter

**操作**  
`なぜ2つで足りる？` を開く。

**ナレーション**  
「定型の18歳確認だけならルールで書けます。AIを使うのは導入時です。サービスごとに異なる目的と現在の過剰取得を読み、許可済みClaim Catalogの中からPolicy案を作ります。曖昧なら自動決定せず、確認へ戻します。」

「この呼び出しは実際にOrcaRouterを通っています。モデル、応答時間、request IDを実測値として残します。利用者の本人情報は分析へ送りません。」

## 2:13–2:37 失効

**操作**  
裏側を閉じ、`Demo Issuerに失効を依頼` を押す。

**ナレーション**  
「共有同意の撤回と、証明の失効は別です。同意撤回は今後の再共有を止めます。今回はDemo Issuerが証明を失効し、NIGHT SCREENが再検証します。」

**画面**  
REVOKEDと再確認待ちを映す。

「同じ証明はもう通りません。サービス側は、再度の年齢確認を求めます。」

## 2:37–2:55 境界と締め

**画面**  
実装済み / 模擬 / 構想を映す。

**ナレーション**  
「このPoCで実装したのは、OrcaRouter分析、同意、署名、検証、期限、失効です。Issuerと利用サービスは模擬。実eKYCやAI Agent Trustは未実装の構想です。」

「本人情報の要求を、必要最小限の証明に。HumanProofです。」

## 撮影チェック

- 最初から失効まで、一度も要件入力フォームを操作しない
- ローディング待ちでは無言にならず、署名・検証の説明を重ねる
- `ORCAROUTER` と実測request IDが見える瞬間を1秒以上残す
- `Demo Trusted Issuer` を拡大せずとも読める大きさにする
- APIがMOCKまたは失敗なら収録を続けない
- 失効後の再確認待ちまで映す
