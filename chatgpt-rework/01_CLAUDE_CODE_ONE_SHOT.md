## HumanProof AI HACK 2026 最終改修

### 目的

現在の「来訪者がサービス要件を入力し、AI分析、同意、発行、検証、失効を一人で操作する」画面を、審査員が一般利用者として迷わず完走できる **Guided Integration Demo** へ再編集する。

公開体験を次の一文と一致させること。

> 架空の18歳以上向け動画配信サービスへ登録する途中でHumanProofを選び、氏名・正確な生年月日・住所・顔写真・身分証画像をサービスへ渡さず、「18歳以上」「実在する人」という署名付き証明だけを共有して登録を完了する。

### 最重要判断

現行のRequirement入力画面を一般利用者向けデモの入口にしない。これはサービス導入時のPolicy Studioであり、一般利用者が登録のたびに入力するものではない。

現行機能は削除せず、次の二層へ分ける。

1. 主体験: NIGHT SCREENへの登録中にHumanProofを利用する
2. 補足: 「なぜ2つで足りる？」からAI Policy StudioとOrcaRouter監査証拠を見る

映画サービスのイラストや説明図を置くだけでは不可。実際にクリックして登録完了まで進むUIを作る。

### 既存実装で維持するもの

- `/api/analyze`
- `/api/proof/quote`
- `/api/proof/issue`
- `/api/proof/verify`
- `/api/proof/revoke`
- provider表示とOrcaRouter監査メタデータ
- Claim Catalog
- PII Shield / block-before-egress
- 署名、pairwise subject、期限、失効、fail-closed検証
- 日本語 / 英語のi18n基盤（現存する場合）

APIや暗号ロジックを全面改修しない。今回の主作業は、保存済みPolicyを前提にした入口と、結果を利用サービスへ返す体験の追加である。

### 主体験の画面遷移

#### Screen 1: NIGHT SCREEN

架空の18歳以上向け動画配信サービス。表示内容:

- `会員登録 / 最後の1ステップ`
- `年齢確認が必要です。`
- `NIGHT SCREENは18歳以上の方のみ利用できます。確認方法を選んでください。`

2つの選択肢:

**従来の確認**

- 身分証をアップロード
- サービスが受け取る例: 氏名、正確な生年月日、住所、顔写真、身分証画像
- 実ファイルアップロードは作らない。比較表示のみであることを明示する

**HumanProof**

- 18歳以上
- 実在する人
- ボタン: `HumanProofを使う`

#### Screen 2: HumanProof Consent

見出し:

`共有するのは、2つの事実だけ。`

サービスへ共有:

- 18歳以上である
- 実在する人である

サービスへ渡さない:

- 氏名
- 正確な生年月日
- 住所
- 顔写真
- 身分証画像

同じ視野内に必ず表示:

`Demo Trusted Issuer / 模擬。本番の本人確認ではありません。`

`証明も個人に関する属性であり、匿名化を意味しません。`

ボタン: `この2つだけ共有する`

ボタン押下後、保存済みのNIGHT SCREEN Policyを使って既存APIを順に呼ぶ。

1. analyze（導入時Policyの実行証拠を得る。利用者の本人情報は送らない）
2. quote
3. issue
4. verify

API障害時は成功を模擬しない。エラーを表示して止める。MOCK providerの場合は画面全体で判別できる表示にする。

#### Screen 3: NIGHT SCREENへ戻る

`登録が完了しました。`

`身分証画像をNIGHT SCREENへ提出せず、視聴を始められます。`

結果:

- 共有した証明: 2
- AIへ送った本人情報値: 0
- サービスへ渡さない項目: 5

注記:

`「個人情報が0」ではありません。共有された2つの属性証明は個人に関する情報です。`

`0` は audit の実測値を使う。絶対的な不存在証明とは書かない。

#### Screen 4: 補足とライフサイクル

3つの操作を分ける。

1. `なぜ2つで足りる？`
2. `共有同意を撤回`
3. `Demo Issuerに失効を依頼`

**なぜ2つで足りる？**

現行のAI分析結果を簡潔に表示:

- 4 data → 2 proofs
- source
- resolved model / response model
- latency
- request ID
- AIへ送った本人情報値
- AIへ送った原本画像数
- proof ID
- expiry

OrcaRouterのロゴ風バッジだけでは不可。実レスポンスの監査値を表示する。

**共有同意を撤回**

今後の再提示を止める。既発行証明を無効化したとは表示しない。

**Demo Issuerに失効を依頼**

既存revoke APIを呼ぶ。操作主体はDemo Issuerと表示する。続けてverifyし、`REVOKED`を確認する。

その後NIGHT SCREEN画面で:

`この証明は、もう通用しません。利用を続けるには年齢確認をやり直す必要があります。`

を表示する。

### AIの意味づけ

次を明記する。

> 定型の18歳確認ひとつならルールで足ります。AIを使うのは、サービスごとに異なる複数目的・曖昧な規約文・現在の過剰取得を、許可済みClaim Catalogに制約されたPolicy案へ変換する導入時です。根拠が足りなければ自動採用せず、人へ確認を戻します。

利用者登録のたびにLLMを呼ぶ設計にはしない。Policyを保存し、実行時はProof Requestとして使う。

可能ならPolicy Studioの例は次の3つを残す。

- 18歳動画: `over_18 + human_verified`
- bot / 複垢対策: `human_verified + unique_person`
- 目的不明: Claimを確定せず clarificationへ

ただし主デモの前に置かない。時間がなければ3例の演出より主体験を優先する。

### 表現上の禁止事項

- `個人情報を一切共有しない`
- `過剰取得と管理リスクをゼロにする`
- `AIでなければ不可能`
- `いつでも利用者が証明を失効できる`
- `完全匿名`
- `実eKYC接続済み`
- `GDPR準拠`
- `世界初` / `競合不在`

置き換え:

- 共有しない具体項目を列挙する
- `過剰取得と管理リスクを抑える`
- `定型例はルールで足りる。AIはPolicy設計支援に使う`
- `利用者は共有同意を撤回できる。Issuerは証明を失効できる`

### デザイン

- 黒背景なし
- 紙に近い明るい背景、黒、深緑、グレー

### テスト

最低限、次を自動テストする。

1. 主体験にサービス要件入力欄がない
2. HumanProof選択 → consent → quote → issue → verify → 登録完了
3. analyzeが `over_18` と `human_verified` を返す
4. 実API応答がなければ成功画面へ進まない
5. 共有同意撤回だけではREVOKEDにならない
6. Demo Issuer失効 → 再verifyでREVOKED
7. Demo / 実装済 / 構想ラベルが存在する
8. `個人情報ゼロ` 等の禁止文言が存在しない

既存テストをすべて維持し、追加テストも通す。

### 完成条件

- 初見30秒で「身分証をサービスへ渡さず、必要な条件だけ証明して登録するもの」と説明できる
- 90秒以内に登録完了まで到達できる
- 一般利用者がサービス要件を入力しない
- `登録完了` がHumanProof内のVALID表示ではなくNIGHT SCREEN側に出る
- 実OrcaRouterの監査証拠を任意で確認できる
- 同意撤回とIssuer失効が別物である
- 失効後にNIGHT SCREENが再確認待ちになる
- 実装済 / 模擬 / 構想が混ざらない

### 最後に出す報告

- 変更ファイル
- 既存機能の再利用箇所
- 実APIで確認した一本道の結果
- MOCK / エラー時の挙動
- 実行したテスト
- 未実装として残したもの

ここに書かれていない新しいプロダクト機能を発明しない。実装中に判断が必要になった場合は、主体験の短さ、誠実表示、既存API再利用の順に優先する。
