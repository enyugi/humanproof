# HumanProof 3分デモ動画 — 最終台本

想定尺: 2分45秒〜3分

事前準備:

- タブ1: `/demo`
- タブ2: `/studio`。代表入力を設定済み
- OrcaRouter実接続を確認。失敗時は実接続部分を撮り直す
- ブラウザ幅はPC。文字が読める倍率に固定

## 0:00–0:28 — IAMmeでアカウント作成と本人確認

**画面**: `/demo`で`デモアカウントを作る`、続けて`本人確認を完了する（模擬）`を操作。確認済みProofが表示されたらNIGHT SCREENへ進む。

**ナレーション**:

「まずIAMmeのデモアカウントを作り、Demo Trusted Issuerで『18歳以上』『実在する人』を確認します。この属性の元確認だけは模擬です。後段の署名、検証、失効は実APIで動きます。」

## 0:28–0:48 — ECでHumanProofを選ぶ

**操作**: `HumanProofを使う`。

**ナレーション**:

「18歳以上向け映像作品を扱う架空のEC、NIGHT SCREENで購入します。18歳以上だと確認したいだけなのに、ECへ氏名、生年月日、住所、身分証画像まで渡す代わりに、IAMmeで証明する方法を選びます。AIは導入時に要件を4つのデータから2つのProofへ整理し、購入時は保存済みPolicyを使います。」

## 0:48–1:12 — 共有確認と明示同意

**画面**: 共有する2つ、共有しない4つ、Demo Trusted Issuerの模擬表示。

**ナレーション**:

「共有するのは『18歳以上』『実在する人』の2つ。氏名、正確な生年月日、住所、身分証画像はNIGHT SCREENへ渡しません。元確認を行うDemo Trusted Issuerは模擬で、本番eKYCではありません。Proofも個人に関する属性で、匿名化を意味しません。」

**操作**: `この2つだけ共有する`。

## 1:12–1:35 — 署名・発行・検証

**ナレーション**:

「同意した内容に対して、短い有効期限を持つ署名付きProofを発行します。NIGHT SCREENは署名、発行者、宛先、有効期限、失効状態を検証します。」

## 1:35–1:53 — サービス上の成果

**画面**: `購入が完了しました`と`VALID`。

**ナレーション**:

「暗号状態のVALIDだけで終わらず、NIGHT SCREENで購入が完了します。共有したProofは2つ。ECへ渡さなかった本人情報は4項目です。個人情報が0という意味ではありません。」

## 1:53–2:23 — AIとOrcaRouter

**画面**: `この購入で使ったPolicy`を見せ、タブ2の`/studio`へ切り替える。代表入力で分析し、4→2とauditを表示。

**ナレーション**:

「購入時には保存済みPolicyを使い、LLMを呼びません。AIを使うのは導入時のPolicy設計です。定型の18歳確認だけならルールで足ります。複数目的や曖昧な規約文を、許可済みClaim Catalogへ制約されたPolicy案へ変えます。」

「この分析は実際にOrcaRouterを通ります。モデル、応答時間、request IDは実レスポンスだけを表示します。利用者の本人情報値を検出した入力は、AI送信前にブロックします。」

## 2:23–2:43 — 失効と再検証

**画面**: タブ1へ戻る。`このProofを失効する`を押し、`REVOKED`を見せる。

**ナレーション**:

「発行時に保有者へ返された秘密コードでProofを失効します。同じProofを再検証するとREVOKEDになり、サービスは年齢確認のやり直しを求めます。永続的な同意管理と再提示停止は、今回のPoCでは未実装です。」

## 2:43–2:58 — 境界と締め

**画面**: LPの実装済み／模擬／構想・未実装。

**ナレーション**:

「実装済みはPolicy分析、同意、署名、検証、期限、失効。Issuerの元確認と利用サービスは模擬。実eKYCやAI Agent Trustは未実装です。」

「本人情報の要求を、必要最小限の証明に。IAMmeの最初のPoC、HumanProofです。」

## 撮影合格条件

- `/demo`で要件入力フォームを操作しない
- IAMmeアカウント作成と模擬本人確認を操作してからECへ進む
- `VALID`と`REVOKED`を実API結果として映す
- `/studio`の実OrcaRouter source / model / latency / request IDを読める状態で2秒以上映す
- 2 Proof / 4 withheldを全編で統一
- Demo Trusted Issuerの模擬表示を映す
- エラー、MOCK、偽の監査値がある収録は使用しない
