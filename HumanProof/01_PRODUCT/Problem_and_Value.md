# Problem and Value

## Problem hypothesis

ユーザーは、年齢や実在性の確認のためだけに、信用度の分からないサービスへ本人確認書類やPIIを繰り返し渡している可能性がある。サービス側も、目的に不要なPIIを保有することで漏洩影響、運用、監査、同意管理の負担を増やしている可能性がある。

## Value by stakeholder

### User

- 本人確認書類を多数のサービスへ配布しない
- 本名や正確な生年月日を出さずに条件を証明する
- 共有内容を確認し、明示的に同意する

### Service

- 必要条件だけを検証する
- 不要なPIIの保有を減らす
- ProofのIssuer、署名、期限、失効を確認する

### Issuer

- 一度確認した属性を、用途別・最小開示で再利用可能にする
- 自らの署名とtrust policyを保つ

## Important caveat

上記の価値が、企業の優先課題・予算・導入意思に結びつくかは未検証。特に「プライバシー配慮」よりも「漏洩損失、本人確認コスト、離脱率、不正、規制対応」が購買理由になる可能性を検証する。
